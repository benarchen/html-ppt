# Goal 003：逐页播放器与宇宙背景动效修复施工清单

## 1．目标

修复当前 HTML 演示稿在屏幕播放时的四类问题：

1. 消除画布顶部、左侧和右侧突兀的播放器黑色留白。
2. 将规则重复的星点背景改为稀疏、位置不规则、缓慢漂移并独立闪烁的星空。
3. 将流星改为从左下方向右上方飞行，并尽量保持在画面对角线左侧。
4. 将默认 HTML 从连续纵向文档改为“一次只显示一页”的演示模式，并提供自然、可降级的逐页切换。

本 Goal 的完成结果应满足：观众打开 `index.html` 后看到的是一个真正的 16∶9 HTML 演示播放器，而不是带有页面间隙的长网页；PDF、PNG、Preflight 和打印仍由同一 HTML 生成，不改变 HTML 作为唯一视觉真相源的架构。

沟通任务：观众应把每张内容理解为独立演示页面，并在不受黑边、重复星点或错误流星方向干扰的情况下专注当前页面。

### 2.2 当前实现证据

- 基线：`main@5e4c4e7`，公开版本 `v0.2.0`，施工清单创建前工作树干净。
- `src/renderer.ts` 的 `.deck` 使用 `grid`、`32px` 间距和 `32px` 内边距，因此屏幕模式天然形成顶部空隙和页面间隔。
- 当前缩放只使用 `min(innerWidth / 1280, innerHeight / 720)`，没有显式的全屏舞台容器，也没有区分屏幕演示与导出检查模式。
- `.slide` 在屏幕媒体中缩放后仍处于普通文档流，所有页面纵向排列，浏览器滚动可以同时看到相邻页面。

- `cosmic-mint` 使用三层重复 `radial-gradient` 生成星点，周期性平铺会形成可见规律。
- 当前流星位于右上区域，运动轨迹由右上向左下，与最新反馈要求相反。

### 2.3 根因判断

问题 1 和问题 4 属于通用播放器／渲染壳，不得在 `cosmic-mint` 中用主题专属负边距或放大裁切掩盖。问题 2 和问题 3 属于 `cosmic-mint` Theme Package，应保持其他主题视觉不变。

## 3．术语与模式契约

- **逻辑画布**：固定为 1280 × 720，内容布局、Preflight 和导出尺寸均以此为准。
- **舞台**：占满浏览器可视区域、承载当前逻辑画布的通用播放器容器。
- **演示模式**：默认屏幕模式；同一时刻只显示一张活动页面，页面不进入连续纵向文档流。
- **全页渲染模式**：供 Preflight、逐页 PNG、主题审核和自动化检查使用；所有页面均可被程序稳定定位和测量。
- **打印模式**：由 `@media print` 控制；所有页面依次输出，每页一个 16∶9 页面。
- **活动页面**：当前展示、可访问且参与键盘焦点的唯一 `.slide`。

模式必须显式区分，禁止依赖浏览器窗口尺寸猜测当前是演示、导出还是打印。

## 6．设计决策

### 6.1 黑边处理

16∶9 视口中，活动页面应完整贴合视口。对于宽屏、竖屏或其他非 16∶9 视口，保留等比 `contain`，舞台剩余区域必须使用当前主题的银河、渐变和稀疏星光延展到视口边缘；纯色填充即使颜色接近页面，也不再视为“铺满”。

禁止以下做法：

- 拉伸 1280 × 720 画布以填满任意比例。
- 使用 `cover` 裁掉标题、页码或安全区。
- 把逻辑画布改为响应式宽高导致内容重新排版。
- 仅把通用黑色换成另一个固定颜色，而不从当前主题取得舞台背景角色。

### 6.2 星空处理

- 删除三层重复平铺的 CSS 星点图案。
- 每张 1280 × 720 页面保留约 8～20 个主星点；银河颗粒和地球点阵不计入此数量。
- 星点位置必须确定性生成，不使用未设种子的 `Math.random()`，同一输入重复构建的 HTML 和 build id 必须稳定。
- 至少使用 3 组不同的闪烁周期和负延迟，建议周期范围为 4～10 秒，避免同步呼吸。
- 漂移必须轻微，建议 12～24 秒内移动不超过 12 个逻辑像素，不能让星空像粒子特效或屏保。
- 亮度只在克制范围内变化，不产生大面积频闪；闪烁频率不得接近高风险快速闪烁。
- 允许按页面索引使用 3～4 个确定性星空变体，避免每页星点完全相同。
- 每颗主星必须独立控制亮度、光晕、周期、延迟和位移；禁止把多颗星合并在同一背景图层后整组同步呼吸。
- 至少一部分星点需要出现短暂但柔和的高亮峰值，肉眼可辨但不得形成快速频闪；漂移轨迹保持 4～12px 的小范围弧形或双轴往返，呈现萤火虫感。

### 6.3 流星处理

- 运动方向定义为：从画布左边缘外进入，向右上方移动，并穿过上边缘离开；可见阶段内 `x` 增大、`y` 减小。
- 起点 `x` 必须小于等于 0，起点 `y` 位于画布高度约 18％～72％；终点 `y` 必须小于 0，终点 `x` 位于画布宽度约 28％～68％，使轨迹集中在屏幕上半区和主对角线之上。
- 每轮随机生成 1～3 颗流星；同一轮内的起点、终点、角度、长度、速度和启动偏移不得完全相同。
- 使用 `crypto.getRandomValues` 生成每次页面会话的显式种子，再由项目内轻量 PRNG 生成序列；禁止直接散落调用未设种子的 `Math.random()`。
- 流星波次间隔必须变化，不得由单一 CSS `infinite` 周期循环；同一次构建的 HTML／IR／build id 仍必须确定。
- 每颗流星使用连续直线位移、平滑缓动、渐入和快速渐隐；不得出现折线、瞬移、回弹或轨迹中途改变方向。
- 单颗流星持续时间冻结为 1.9～2.6 秒，避免 0.1.4 的 0.72～1.28 秒产生一闪而过的观感。
- 流星位于内容层之后；经过文本区域时透明度和光晕不能降低正文对比度。
- 周期与延迟保持非同步、确定性；打印与减少动态效果环境冻结为低亮度代表帧。

### 6.4 逐页切换

- 默认只展示活动页，其他页不可见、不可聚焦，并带正确的 `aria-hidden` 状态。
- 前进键：`ArrowRight`、`ArrowDown`、`PageDown`、`Space`。
- 后退键：`ArrowLeft`、`ArrowUp`、`PageUp`、`Shift+Space`。
- `Home` 跳到第一页，`End` 跳到最后一页。
- 滚轮／触控板按连续手势状态处理：累计主轴位移达到 24px 后翻一页；同方向衰减尾流不再翻页；事件间隔达到 56ms，或尾流降到 10px 以下后重新加速到至少 14px，均视为新手势；输入静默 120ms 后强制复位，反向输入立即重置并允许返回。
- 页面状态写入稳定 URL hash；无效 hash 回退到第一页，不能抛出运行时异常。
- 建议切换时长为 280～420ms，使用低幅度位移加透明度；不得使用翻转、3D 旋转、弹跳或大幅缩放。
- 快速重复输入必须串行化或合并，不能出现两页同时活动、页码错乱或过渡卡死。
- `prefers-reduced-motion: reduce` 下立即切页，只保留状态变化，不播放位移动画和闪烁漂移。

## 12．边界与异常清单

- 视口为 16∶9、超宽、4∶3、竖屏和小尺寸。
- 浏览器缩放不为 100％、窗口运行中改变尺寸。
- 第一页、最后一页、单页文稿和 27 页长文稿。
- hash 缺失、越界、格式错误和指向不存在 slide id。
- 长滚轮手势、触控板惯性、快速反向切换和按键长按。
- 输入焦点位于链接或未来可交互元素时的键盘事件。
- 动画进行中切换窗口、刷新、热重载或改变视口。
- `prefers-reduced-motion`、打印媒体和无动画截图。
- Preflight、单页 PNG 截图、PDF 打印和主题审核页访问全部隐藏页面。
- JavaScript 未执行时至少保留可读的降级文档，不允许空白页面。
- 星空、银河、地球和流星图层的 z-index 不得盖住正文。
- 所有动画只使用 transform／opacity 或等价低成本属性，避免持续布局抖动。

## 15．阻塞与停止条件

出现以下任一情况时停止施工并请求用户决策：

- 用户要求“完全无留白”但同时要求在任意非 16∶9 视口不裁切、不拉伸，三者无法同时满足；需在主题化边带与裁切之间明确取舍。
- 逐页演示模式与现有外部集成依赖连续 DOM 流，且无法通过显式全页渲染模式兼容。
- 流星“对角线左侧”的目标区域在真实内容页持续遮挡标题，需要用户在装饰可见度与内容优先级之间选择。
- 现有依赖无法实现可靠触控手势，必须新增依赖。
- 动效在目标浏览器产生明显掉帧或影响导出确定性。
- 需要修改 Markdown Spec、Deck IR、布局系统、CI／CD、发布配置或公开远端。

## 16．Goal 状态维护

- `planned`：施工清单完成，但用户尚未明确要求开始实施。
- `active`：用户明确要求实施，启动条件满足，至少一个阶段进行中。
- `blocked`：同一阻塞条件连续出现且无法在授权范围内推进。

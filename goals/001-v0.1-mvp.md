# Goal 001：html-ppt v0.1 MVP 施工清单

## 1．目标

完成一个可以在本地重复运行的 `v0.1 MVP`：

> 输入一份符合项目规范的 Markdown，经由 Markdown AST 和 Deck IR，使用至少两个主题生成 HTML，并从同一 HTML 导出 PDF 与逐页 PNG；构建过程能够发现关键内容、资源和布局错误，并产出可追溯的检查报告。

本 Goal 是后续 Goal 模式施工的唯一执行清单。所有勾选状态必须与代码、测试和 `ROADMAP.md` 中的真实状态一致。

## 2．启动条件

- [x] 项目级 `AGENTS.md` 已建立。
- [x] `README.md` 已建立。
- [x] `ROADMAP.md` 已建立。
- [x] `docs/architecture.md` 已建立。
- [x] 用户明确要求开始执行本 Goal。
- [x] 实施前记录 Node.js、npm 和 Chromium 的本地可用状态。

未满足“用户明确要求开始执行本 Goal”时，只能维护清单和文档，不得开始安装依赖或实现代码。

## 3．完成定义

只有同时满足以下条件，本 Goal 才能标记为 `complete`：

- [x] 一份规范 Markdown 能转换为通过 Schema 校验的 Deck IR。
- [x] 同一份 Markdown 不经修改即可使用至少两个主题生成 HTML。
- [x] HTML 使用固定 `1280 × 720` 逻辑画布，并能在浏览器中等比例预览。
- [x] PDF 和逐页 PNG 均由同一份 HTML 构建产物生成。
- [x] PDF 页数与 HTML slide 数量一致，页面尺寸为 `13.333in × 7.5in`。
- [x] PNG 数量与 HTML slide 数量一致，默认尺寸为 `2560 × 1440`。
- [x] 核心错误可以被 Preflight 发现，并通过非零退出码阻止成功交付。
- [x] 所有自动化测试、主题契约测试和端到端自测通过。
- [x] 所有计划交付文档已完成并与实现一致。
- [x] `ROADMAP.md` 已记录实际完成内容、验证命令、验证结果、阻塞和下一步。
- [x] 工作区中没有密钥、临时调试文件、无关改动和由本次实现造成的孤儿代码。

任何一项未满足，都不能宣告 Goal 完成。

## 4．执行协议

每次 Goal 模式施工必须按以下顺序执行：

1. 阅读 `AGENTS.md`、本文件、`ROADMAP.md` 和相关 `docs/` → 验证：确认当前阶段、未完成项和边界。
2. 选择第一个依赖已满足的未完成任务 → 验证：本轮范围清晰且不跨越未完成的质量门禁。
3. 多模块改动先给出步骤、改动点和验证方式 → 验证：不存在隐含的架构或依赖变更。
4. 先补复现、Schema 示例或失败测试，再实现能力 → 验证：测试在修复前能证明问题或缺口。
5. 实现最小改动并执行对应自测 → 验证：相关测试和质量门禁通过。
6. 更新本文件的勾选状态和证据，再同步 `ROADMAP.md` → 验证：文档不领先于实现。
7. 阶段完成后执行阶段回归，最终完成后执行全量验收 → 验证：没有依赖局部测试掩盖集成问题。

禁止仅凭“命令执行过”勾选任务；必须检查退出码、输出产物和关键内容。

## 5．施工边界

### 5.1 本 Goal 范围内

- Node.js＋TypeScript 单项目初始化。
- Markdown 输入规范、解析和校验。
- Deck IR Schema、类型和序列化。
- Theme Package Contract、基础主题和第二主题。
- 确定性的布局选择和 HTML 渲染。
- 12 种架构既定布局的基础实现。
- 本地 HTML 预览。
- Playwright 驱动的 PDF 和 PNG 导出。
- Preflight、单元测试、契约测试、集成测试和视觉回归基线。
- 参考图风格提取协议、主题模板和验收样张流程。
- CLI、示例、使用文档和最终交付报告。

### 5.2 明确不在本 Goal 范围内

- 可视化拖拽编辑器。
- 在线 SaaS、账号系统、多人协作和云端存储。
- 生产部署、公开发布、npm publish 和 CI/CD 修改。
- 任意 HTML／CSS 到可编辑 PPTX 的无损转换。
- `pptx-editable` 实现。
- 自动生成演讲内容、事实研究或文案润色。
- 对任意第三方网页执行抓取和样式复制。
- 4∶3、A4、竖版等非 16∶9 画布。
- 视频、音频、复杂动画和演讲者控制台。
- 未提供使用权的字体、logo、图片和专有素材。

### 5.3 不可突破的工程边界

- HTML 始终是唯一视觉真相源。
- Markdown 必须先进入 Deck IR，禁止直接耦合主题 CSS。
- 主题必须实现统一 Theme Contract，禁止按单份文稿写一次性主题分支。
- 默认不执行 Markdown 中的脚本或任意 HTML。
- 渲染和导出默认不访问网络；资源必须本地化或明确失败。
- 不通过无限缩小字号、隐藏元素、截断内容或忽略错误来通过验收。
- 不安装全局依赖，不修改系统配置，不修改 `.env`、密钥或账号配置。
- 不删除文件，不执行 Git 回滚、清理、改历史、推送或发布；如确有需要，必须先获得用户确认。
- 不为了通过测试修改与本 Goal 无关的代码或格式。

## 6．技术基线与依赖门禁

### 6.1 默认技术基线

- 运行时：本地已安装且仍受维护的 Node.js LTS。
- 语言：TypeScript，开启严格类型检查。
- 包管理：npm，避免依赖额外的全局包管理器。
- Markdown：`unified`／`remark` 生态。
- 浏览器渲染：Playwright Chromium。
- 输出：静态 HTML、PDF、PNG、JSON 检查报告。

### 6.2 添加依赖前检查

每个新依赖都必须回答并记录：

- [x] 标准库或现有依赖是否已经能够完成任务。
- [x] 依赖是否直接服务于本 Goal，而非未来假设。
- [x] 官方仓库最近是否仍有维护活动。
- [x] issue 和发布记录是否显示项目仍可维护。
- [x] 许可证是否允许本项目使用。
- [x] 是否会引入重复能力或显著增加构建体积。

依赖检查结果记录到 `docs/dependencies.md`。不得先安装再补理由。

## 9．阻塞与停止条件

遇到以下情况必须停止对应施工并向用户说明，不得自行扩大范围：

- 需要删除文件或目录。
- 需要覆盖或丢弃现有工作区修改。
- 需要安装全局依赖、修改系统配置或 `.env`。
- 需要修改 CI/CD、公开发布、部署、推送或打标签。
- 需要用户提供有授权要求的字体、图片、logo 或参考图。
- 发现架构文档与已确认目标存在实质冲突。
- 可编辑 PPTX 成为本次验收必需项。
- 实施需要引入在线服务、外部 API、账号或长期维护基础设施。

普通技术问题不构成停止理由。应先执行安全的本地诊断、查阅官方文档、缩小复现并记录证据。
